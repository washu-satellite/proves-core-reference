# Cycle K plan — bench startup sequence (`sequences/bench_startup.seq`)

Branch `fix/c08-c11` @ 6296ef32 (= `main` e1eced14 + Cycle J's two fixes), Cycle I and Cycle J tooling still uncommitted
in the tree (frozen paths as in `cycle-j-plan/README.md` §Hazards, plus Cycle J's three tooling files). Plan only: no
code, tests or commits were made while writing it. `$R`, `$PY`, `P` as in Cycle J.

**Why.** `sequences/startup.seq` is dispatched on the first 1 Hz tick of **every** boot (`StartupManager.cpp:375-383`,
`STARTUP_SEQUENCE_FILE` default `/seq/startup.bin`, `StartupManager.fpp:87`). On a bench it does four things nobody
wants: line 7 `R00:45:00 antennaDeployer.DEPLOY` fires the burn wire 45 min after power-on; line 17 `lora.TRANSMIT ENABLED`
keys the radio; line 20 `modeManager.EXIT_SAFE_MODE` turns the faces on; line 22 `detumbleManager.SET_MODE, AUTO` torques
the coils whenever the board is moved. `ARMED=false` does **not** stop any of it — it only skips the quiescence wait
(`:426-434`). The hard-coded radio enable is compiled out on this fork (`DEFAULT_STARTUP_VALUE == 0`,
`test_StartupManager_Persistence.cpp:592`), so the sequence file is the only thing to fix.

**What this cycle delivers.** A generated, tracked bench variant of the sequence with those commands removed and nothing
else changed; a generator script whose `--check` mode fails the gate when the variant drifts from `startup.seq` (the
same shape as `doc_status.py --check`); requirement rows `BENCH-1..2`; and the bench procedure that selects it. The
flight file is untouched — it stays the home of the baseline cadence (D-006).

## 1. Normative (tests derive from these only)

### 1.1 Script — `scripts/make_bench_sequence.py`
```
$PY scripts/make_bench_sequence.py [--source PATH] [--output PATH] [--stdout | --check]
```
| Flag | Default | Meaning |
|---|---|---|
| `--source` | `sequences/startup.seq` | the flight sequence read |
| `--output` | `sequences/bench_startup.seq` | the bench sequence written (default mode) or compared (`--check`) |
| `--stdout` | — | print the generated text instead of writing |
| `--check` | — | write nothing; exit 0 iff the file at `--output` equals the generated text byte for byte |

Standard library only. Default mode writes `--output` and prints `wrote <path>`. Exit codes: `0` success (or `--check`
equal); `1` only in `--check` mode, with one stdout line `bench_startup.seq: stale` or `bench_startup.seq: missing`
(the basename of `--output`); `2` when `--source` cannot be read — nothing on stdout, one stderr line
`error: <what> (<path>)`.

### 1.2 Generation rule
A *line* is one line of the source. A *command line* is a line whose first non-blank token matches `R\d\d:\d\d:\d\d` or
`A\d\d\d\d-\d\d\dT\d\d:\d\d:\d\d`; its *command* is the following run of characters up to the first whitespace **or comma** (so `SET_MODE, AUTO` has
command `…SET_MODE`); its *first argument* is the text after the command up to the first `;` or end of line, with
leading commas and whitespace removed, then the first whitespace-delimited token of that (empty if none). (Amended
2026-09-27, review amendment 4.) A *comment line* is a line whose first non-blank character is `;`.

The output is the header (§1.3) followed by every source line in order, byte for byte, **except**:
1. a command line whose command is `ReferenceDeployment.antennaDeployer.DEPLOY`,
   `ReferenceDeployment.modeManager.EXIT_SAFE_MODE` or `ReferenceDeployment.detumbleManager.SET_MODE` (any argument);
2. a command line whose command is `ReferenceDeployment.lora.TRANSMIT` **and** whose first argument is `ENABLED`
   (`TRANSMIT, DISABLED` is kept);
3. a comment line immediately preceding a line dropped by rule 1 or 2.

Blank lines *inside* the sequence are kept; blank lines at the **end** of the output (every blank line after the last
non-blank line) are dropped, so the file ends in exactly one `\n` — the repo's `end-of-file-fixer` hook
(`.pre-commit-config.yaml:6`) requires it and would otherwise rewrite the tracked file. Nothing else is added, reordered
or reformatted. (Amended 2026-09-27, review amendment 5.) On the tree at 6296ef32 the dropped lines are `startup.seq` 7,
17, 19 (comment), 20, 22, 23, and the blank lines 15, 16, 18, 21 then trail and are dropped too: the output ends after
line 14 (`BANDWIDTH_TX_PRM_SET`).
